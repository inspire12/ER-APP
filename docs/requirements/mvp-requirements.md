# 응급실 스마트 퇴원 안내 MVP 요구사항 분석서

- 문서 버전: 0.3
- 작성일: 2026-09-06
- 상태: 초안

## 1. 목적

응급실 경증 환자에게 의료진이 검토한 퇴원 안내문을 모바일로 제공한다. 의료진은 진료 내용을 입력하고, 시스템이 추천한 사전 검수 안내문을 환자 상태와 연결한 뒤 직접 확인·수정하여 QR로 발급한다.

본 문서는 [전체 제품 구상](../product/product-concept.md) 중 `MVP 1: 안내문 생성과 전달`에 해당하는 범위를 다룬다.

## 2. MVP 원칙

- AI가 새로운 의료 안내문을 자유롭게 작성하지 않는다.
- 병원에서 미리 검수한 질환별 안내문을 사용한다.
- AI는 진료정보 구조화와 적합한 템플릿 추천에 사용한다.
- AI가 실패해도 의료진이 직접 템플릿을 선택할 수 있어야 한다.
- 환자에게 공개하기 전 의료진의 최종 승인을 반드시 거친다.

## 3. 사용자

### 의료진(운영자)

- 진료 내용을 입력한다.
- 추천 또는 직접 선택 방식으로 안내문 템플릿을 결정한다.
- 환자별 정보와 안내문을 검토·수정한다.
- 최종 승인 후 환자 링크와 QR을 발급한다.
- 질환별 안내 콘텐츠를 등록·수정·비활성화한다.

### 환자

- QR을 스캔하거나 링크를 눌러 퇴원 안내문을 확인한다.
- 별도 앱 설치 없이 휴대폰 브라우저에서 내용을 읽는다.

## 4. 핵심 사용 흐름

1. 의료진이 진료 내용을 텍스트 또는 기기의 기본 받아쓰기로 입력한다.
2. AI가 진단명, 증상, 검사·진찰 소견, 치료 및 처방 내용을 구조화한다.
3. 시스템이 적합한 안내문 템플릿을 추천한다.
4. 의료진이 추천 템플릿을 선택하거나 다른 템플릿을 직접 선택한다.
5. 시스템이 환자별 정보와 검수된 고정 안내문을 결합한다.
6. 의료진이 최종 안내문을 수정하고 승인한다.
7. 승인 후 환자 링크와 QR을 동시에 발급한다.
8. 환자는 휴대폰에서 승인된 안내문을 확인한다.

### 콘텐츠 관리 흐름

1. 운영자가 질환별 안내 콘텐츠 목록을 연다.
2. 질환명과 안내 항목을 입력하거나 수정한다.
3. 저장 전 환자 화면 미리보기를 확인한다.
4. 검수를 마친 콘텐츠만 활성화한다.

## 5. 기능 요구사항

### FR-01 진료정보 입력

- 의료진은 자유 형식의 진료 내용을 입력할 수 있어야 한다.
- MVP 1에서는 운영체제나 브라우저의 기본 받아쓰기를 음성 입력으로 사용한다.
- 앱 내부 마이크 녹음과 STT 자동 변환은 MVP 2에서 제공한다.
- API Key가 없는 테스트 환경에서는 데모 데이터를 사용할 수 있어야 한다.

### FR-02 진료정보 구조화

- 시스템은 입력에서 다음 정보를 추출해야 한다.
  - 진단명 또는 의심 진단
  - 주요 증상
  - 검사 소견
  - 진찰 소견
  - 응급실 치료 내용
  - 처방약
  - 추적 진료 계획
- 입력에 없는 정보는 임의로 생성하지 않아야 한다.

### FR-03 템플릿 추천 및 선택

- AI는 적합한 템플릿 후보를 추천해야 한다.
- 의료진은 추천 결과와 관계없이 템플릿을 직접 선택할 수 있어야 한다.
- 매핑이 불확실하면 자동 선택하지 않고 의료진 확인을 요청해야 한다.

### FR-04 질환별 콘텐츠 관리

- 질환별 안내 콘텐츠는 코드가 아닌 DB에 저장해야 한다.
- 운영자는 화면에서 콘텐츠를 등록·조회·수정·비활성화할 수 있어야 한다.
- 콘텐츠 입력 항목은 다음을 포함해야 한다.
  - 질환명
  - 질환 별칭 및 검색어
  - 처방·복약 안내
  - 퇴원 후 생활·식이·자가관리 안내
  - 즉시 재내원해야 하는 경고 증상
  - 운영 메모
  - 상태(초안·활성·비활성)
- 여러 문단과 목록을 입력할 수 있는 큰 텍스트 입력창을 제공해야 한다.
- 저장 전 환자 화면에서의 표시 결과를 미리보기할 수 있어야 한다.
- 활성 콘텐츠만 AI 매핑과 수동 선택 목록에 사용해야 한다.
- 삭제 대신 비활성화를 기본으로 사용해야 한다.

### FR-05 안내문 조합

- 안내문은 병원 검수 고정 문구와 환자별 정보로 구성해야 한다.
- 고정 문구에는 생활수칙, 예상 회복 과정, 재내원 기준이 포함되어야 한다.
- 환자별 정보에는 진단명, 검사·진찰 소견, 치료 및 처방 내용이 포함되어야 한다.

### FR-06 의료진 검토 및 승인

- 의료진은 발급 전에 모든 환자별 내용을 확인하고 수정할 수 있어야 한다.
- 승인 전에는 환자 링크와 QR을 발급하지 않아야 한다.
- 승인된 안내문에는 사용한 템플릿 버전이 기록되어야 한다.

### FR-07 환자 링크 및 QR

- 승인 후 환자 링크와 QR 코드가 같은 화면에 함께 표시되어야 한다.
- QR과 링크는 동일한 안내문을 열어야 한다.
- 다른 휴대폰과 브라우저에서도 안내문을 조회할 수 있어야 한다.
- QR에는 진료 내용이 아니라 추측하기 어려운 접근 토큰만 포함해야 한다.

### FR-08 환자 화면

- 환자 화면에는 다음 항목을 표시해야 한다.
  - 진단명 또는 의심 질환
  - 검사 및 진찰 결과
  - 처방 및 복약 안내
  - 생활수칙
  - 예상 회복 과정
  - 즉시 재내원해야 하는 증상
  - 추적 진료 계획
- 모바일 화면에서 큰 글자와 명확한 정보 구분을 사용해야 한다.
- 위험 증상은 다른 내용보다 눈에 띄게 표시해야 한다.

## 6. 콘텐츠 요구사항

- 질환별 안내문은 의료진이 작성하거나 검수해야 한다.
- 환자가 이해하기 쉬운 짧은 문장을 사용한다.
- 진단이 확정되지 않은 경우 `의심` 또는 `가능성` 표현을 유지한다.
- 약물명·용법·용량은 의료진 입력이나 검수된 데이터만 사용한다.
- AI가 약물 복용법을 추정하거나 새로운 약을 추천해서는 안 된다.
- 템플릿에는 작성자, 검수자, 버전, 검수일을 기록한다.
- 기존 환자에게 이미 발급된 안내문은 후속 콘텐츠 수정에 의해 자동으로 바뀌지 않도록 발급 시점의 내용을 보관한다.

## 7. 비기능 요구사항

- 환자 링크는 HTTPS 환경에서 제공해야 한다.
- 환자 이름, 주민등록번호, 전화번호를 QR에 직접 포함하지 않는다.
- 의사용 화면과 환자용 화면을 분리해야 한다.
- 안내문 생성·수정·승인 이력을 기록할 수 있는 구조여야 한다.
- AI 호출이 실패해도 수동 템플릿 선택과 발급이 가능해야 한다.

## 8. MVP 완료 조건

- 의료진이 진료 내용을 입력할 수 있다.
- AI가 구조화 결과와 템플릿 후보를 제시한다.
- 의료진이 템플릿을 직접 변경할 수 있다.
- 운영자가 DB에 질환별 안내 콘텐츠를 등록·수정·비활성화할 수 있다.
- 저장 전 환자용 안내문을 미리보기할 수 있다.
- 의료진이 환자별 내용을 수정하고 승인할 수 있다.
- 승인 전에는 QR과 환자 링크가 생성되지 않는다.
- 승인 후 QR과 환자 링크가 함께 표시된다.
- 별도 휴대폰에서 환자 안내문을 정상적으로 조회할 수 있다.

## 9. 추후 확장 후보

- FAQ 바로가기
- 환자 상태 확인 및 악화 기록
- 검수된 지식 범위 내 환자 질문 기능
- 복약 타이머 및 웹 푸시
- 카카오 알림톡
- 의료진 경과 대시보드와 악화 알림
- EMR 및 처방정보 연동
- 다국어 안내문
- 소아·임산부·중증질환 템플릿
